# Granthalaya — notes for Claude Code

A shelf for everything you read and watch (books, films, TV seasons, essays), in hand-painted scenes. Started as Sarthak's own library; since Phase 1 anyone can sign in with Google and keep a shelf at `/@username`. Astro 5 rendered on request (`output: 'server'`) on Vercel (functions in Mumbai, `bom1`), with a Supabase database. Every push to `main` deploys.

## How the project is organised

- **Database:** `supabase/schema.sql` is the whole schema: tables, privacy rules (row level security), triggers and grants. Change it there, and put the extra SQL for the live database in `supabase/changes/` (numbered) for Sarthak to run in Supabase → SQL Editor. Tables: `profiles`, `profile_details` (bio, links, favourites; `pinned_line` is no longer used), `username_history`, `titles` (the shared catalogue), `logs` (one row per visit to a title; its `notes`, `tagline` and `spoiler` are the review), `review_likes` and `review_comments`, `highlights` (the old lines, kept but no longer shown), `threads` and `thread_items` (shown on the site as **Collections**), `blocks`, `reports` (a profile, an entry or a comment).
- **One door to the data:** pages read shelves, profiles and collections only through `src/lib/data.ts` (`loadProfile`, `loadShelf`, `loadVisits`, `loadCollections`, `loadFeatured`, and `shelfReviews` for the reviews on a shelf). A title's reviews, likes and comments come from `src/lib/reviews.ts` (`title_reviews()` in the database, security invoker). Rows become `Entry` objects shaped like the old markdown entries, so `Cover`, `Tile` and the pages share one shape.
- **Who's visiting:** `src/middleware.ts` makes a Supabase client from the visitor's cookies (`Astro.locals.supabase`), reads the signed-in person (`locals.user`) and their profile (`locals.me`). Signed in without a username yet means a redirect to `/welcome`. It also redirects old addresses (`/library/x` → `/@sarthak/library/x`).
- **Two database clients** (`src/lib/supabase.ts`): `serverClient` acts as the visitor, so the database's privacy rules always apply. `adminClient` uses the secret key and is only for the shared catalogue (`src/lib/titles.ts`), username checks, account deletion, the blocked list in Settings and the admin page, always after the code has checked who's asking. Never use it to read someone's shelf for display.
- **Pages:** `src/pages/index.astro` (discovery first: signed out, the painting, one line and the Google button, then rows of popular films, books and series; signed in, "Welcome, Name." for an empty shelf, else "Welcome back, Name." with Continue and Recently, then the same rows), `@[username]/` (profile, library, entry `library/[slug]`, diary, reviews, collections, stats, rss), `add.astro`, `settings.astro` (tabs: Profile, Privacy, Your data, Account, kept in the address as `#privacy` etc.), `welcome.astro`, `signin.astro`, `admin.astro`, `about`, `privacy`, `terms`, `404`. Every `/@username` page starts with `openShelf()` from `src/lib/shelfpage.ts`.
- **Navigation:** the top bar is for the whole site: Films, Books, Essays and, signed in only, **My shelf** (going to `/@you/library/`, shown as current on any of your own `/@you/...` pages), all as uppercase links in the middle; on the right, Search and Dark mode (plain icons, no circles), Add and the account picture. On a phone the nav links are the bottom bar and My shelf is a fourth tab there. A shelf's own pages are only in its tabs: Profile · Library · Diary · Collections · Stats (`ShelfTabs.astro`). "Want to" is a Library filter (`?status=want`), not a tab. Reviews (`/@username/reviews/`) is reached from the profile's Reviews count; `/lines/` redirects there. The account menu is Profile · Settings · Reports (admins) · Sign out. Old addresses (`/threads`, `/notes`, `/@x/threads/...`, `/@x/notes/`, `/@x/lines/`) redirect in `src/middleware.ts`.
- **APIs** in `src/pages/api/`: `log` (add, change, remove entries, with the review's tagline and spoiler switch), `review` (like, comment, delete a comment), `lookup` (search), `block`, `report` (profile, entry or comment), `profile` (sections: profile, favourites, links, photo, flag), `welcome`, `username`, `export` (one zip of spreadsheets, made by `src/lib/zip.ts`), `account`, `admin`, `search`, `keepalive`. Sign-in lives in `src/pages/auth/` (Google → `/auth/callback` → `/welcome` for new people).
- **Kinds and status tags:** `src/lib/kinds.ts` (`STATUSES`, labels, usernames, social links). The database checks the same rules.
- **Title pages (catalogue first):** every film, show and book has a public page whether or not anyone has logged it: `/film/<tmdb id>-<name>/`, `/tv/<tmdb id>-<name>/`, `/book/<ol key>-<name>/` (or `/book/gb-<google id>/`), people at `/person/<tmdb id>-<name>/` and `/author/<ol key>-<name>/`. Data comes from `src/lib/catalog/` (`tmdb.ts`, `books.ts`; `fetch.ts` adds a time limit and a small in-memory cache, and its base addresses can be pointed at a test server with `TMDB_API_BASE`, `OPENLIBRARY_BASE`, `GOOGLE_BOOKS_BASE`). `catalog/onsite.ts` adds what Granthalaya knows: counts, collections, your own logs (`onSite`), your status on list posters (`myMarks`), and fills in missing TMDB/Open Library ids for older catalogue rows the first time their page is opened (`healFilm`, `healBook`). A catalogue row's page is `titlePageHref()`. The pages share `components/title/TitleLayout.astro` (slots: `poster`, `side`, the title and summary, `more` for the tabs, `panel`, `below`); on a phone it shows poster, title, your log, where to watch, then the tabs.
- **Log panel** (`components/LogPanel.astro`): save, status, half-star rating, a note, add to a collection, share. Before a title is in our catalogue the buttons carry `hit` and the server adds it on the first action. TV is logged per season (one panel body per season, with a picker). Its clicks are handled in `Base.astro` (`data-log-new`, `data-rate`, `data-write`, `data-collect`, `data-quick-add`).
- **Front pages and rows:** `/films/`, `/films/?kind=tv` and `/books/` with no filters are front pages: rows of posters (`components/title/PosterRow.astro`, scrolls sideways, arrows at the sides of the row and only with a mouse; the Popular this week row is the large one, `big: true` in `rows.ts`, four posters across) and chips to browse by genre, language, service and decade. What goes in each row, and its "See all" address, is in `src/lib/catalog/rows.ts` (`filmRows`, `bookRows`, `homeRows`; `markRows` adds the visitor's own statuses in one lookup). "Popular this week" is TMDB's trending list and Open Library's weekly trending. Any filter in the address turns the page into a grid: dense, posters only (`.pgrid`, `bare` on `PosterTile`; the name shows on hover, a cover-less tile shows title and author on its placeholder), 40 films or 48 books a page, with `YearStrip.astro` under the bar once a decade or year is chosen. The filter bar (`components/title/Filters.astro`) is one joined strip of capitalised parts whose lists open on hover; every choice is a link, and a value like `decade=1980` sets that address part.
- **Lists:** `/films/` (with `?kind=tv`) and `/books/` filter by genre or subject, year or decade, language, streaming service (India) and order; every linked year, genre, subject and language on a title page points here. Open Library merges every edition's subjects and languages into the work, so famous books match almost everything: book lists use subject keys, leave fiction out of factual subjects, order "Popular" by what readers log (by editions for Indian languages and plays), and list a book under a fiction genre only when it has both the subject key and the matching shelf category tag (`SHELF_CATEGORY` in `books.ts`); factual subjects leave out books tagged with a neighbouring subject (`NEIGHBOURS`). Neither is used with a language filter, and the language filter asks for that language's own literature ("Marathi fiction" and so on) minus English and American literature. Films' "Highest rated" needs a minimum number of votes and leaves out unreleased films. Open Library's Marathi and Hindi coverage is thin; curated lists are planned to fill that gap. Google Books needs `GOOGLE_BOOKS_API_KEY` in practice: without it, it answers "too many requests" most of the time. Credits for TMDB, JustWatch and the book sources must stay on these pages and on About.
- **Search** (⌘K, `/`, and the Add button): your shelf first, then films and TV, books, people and members, from `/api/search?q=`.
- **Collections** can be made and edited by their owner: "Add to a collection" on title and entry pages (`/api/collection`), a "Make it" box on the Collections tab, and `?edit=1` on a collection page (name, intro, a line about each title, order, remove, delete). Items can be titles that aren't on the owner's shelf; they link to the title page.
- **Catalogue:** `src/lib/lookup.ts` finds things (Open Library for books, TMDB for films and TV seasons, pasted links); `src/lib/titles.ts` adds them to `titles` once, so the second person to add a film gets its cover, runtime and facts instantly. Covers are only taken from `image.tmdb.org`, `covers.openlibrary.org` and, with the shops' permission, Akshardhara's folder on `cdn.shopify.com` and BookGanga's `/eBooks/Content/images/books/` folder. **A shop's cover is never loaded from the shop by visitors:** the address is stored in `titles.cover_url` (with `cover_from`) and pages show it only through `/api/cover` (`viaCover()` in `src/lib/images.ts`), which Vercel's CDN keeps; a shop can ask for a book or cover to be hidden from the admin page (`shop_books.hidden` / `cover_hidden`), and the import never brings it back; the 20 old covers stay in `public/covers` and are referenced as `/covers/<file>.jpg`.
- **Shop books** (`scripts/shops/`, `shop_books`, 010): Marathi and Hindi books from Akshardhara and BookGanga's best-seller lists, with their permission. `fetch.mjs` reads the lists politely, `match.mjs` matches them to our catalogue and Open Library (dry run by default; `--write` saves, only when Sarthak asks; decisions in `private/catalogues/decisions.json`). Non-fiction is kept only when literary (biography, memoir, essays, history, travel). They give "Buy at" links and a credit on book pages, our own records in search and in the Books > Marathi / Hindi lists (`src/lib/catalog/shopbooks.ts`), and hiding on the admin page.
- **Facts:** `src/lib/trivia.mjs` finds the Wikipedia page and asks a free AI model (Gemini, then Groq) for 3 facts from that page only. Run after saving, in the background (`waitUntil`); `npm run trivia` fills in titles still missing them. Facts: under 30 words, no em dashes, never the plot.
- **Reviews and comments are untrusted text:** show reviews with `md()` from `src/lib/md.ts` (paragraphs, italics, bold, http links only). Never `set:html` anything else people wrote.
- **Design:** `src/styles/global.css` holds the tokens for light and dark (`html[data-theme]`); Starwind UI + Tailwind 4 are set up (`src/styles/starwind.css`, `src/components/starwind/`), plus our own pieces in `src/components/ui/` (`StatusTag`, `StatusIcon`, `SectionHead`, `SocialLink`, `GoogleButton`). Watch for class names that clash with `global.css` (`.foot`, `.date`, `.key` are taken).
- **The mark** (`src/lib/mark.ts`) is the bookmark-and-film-strip logo. It means **save** and **loading**, nothing else: `ui/Mark.astro` is the Save icon (an outline that fills from the top and becomes the logo when its button has `aria-pressed="true"` or `.is-saved`; `solid` for status icons), `.ink` is the small loader inside busy buttons (`aria-busy="true"` swaps the icon for it), and `ui/Drawn.astro` is the loader shown when a page takes more than about half a second. Saving shows a toast (no Undo button: tapping the filled bookmark again takes the plain save back, and removing a whole entry asks first). All of it holds still with reduced motion.
- **Limits on costly addresses:** `src/lib/ratelimit.ts` (called from `middleware.ts`) refuses a visitor who asks for `/api/search`, drawn cards or `/api/cover` too often (429; the memory of one running copy, so only a first fence). The real limits are Vercel's firewall rules: `docs/rate-limits.md`.
- **Turnstile on this computer:** `src/lib/turnstile.ts` uses Cloudflare's public test keys only when `npm run dev` runs on localhost (`import.meta.env.DEV`), so `/welcome` can be finished locally. Builds never use them.
- **Contact:** `site.contact` (`src/data/site.ts`) is shown on Privacy and Terms.
- **Polish rules** (in `global.css`): every interactive thing has hover, pressed (slight shrink), focus and disabled states; transitions name their properties and stay around 0.2s; numbers use tabular figures; covers get a hairline outline; touch targets are at least 40px. Tailwind's reset removes the browser's centring of dialogs, so `global.css` puts it back.
- `public/art/` holds the page paintings (day and night), shown as CSS backgrounds with `.art` and `--day`/`--night`. `.melt` fades a painting into the page, `.bleed` runs it full width. `src/components/Valley.astro` is the footer painting; its shepherd says the title's own line on title and entry pages, else a weekly line from `site.lines`.
- `src/content/` (the old markdown library) is kept as a backup and as the source for `npm run migrate`. The site no longer reads it.
- `astro.config.mjs` → `security.allowedDomains` lists the site's addresses (the main one and `*.vercel.app` previews). Astro only trusts the address Vercel passes on for these, so a custom domain must be added there too, or sign-in and saving break on it (Astro would think the page is at `https://localhost`).
- `vercel.json`: functions in `bom1` (next to the database in Mumbai) and a daily cron to `/api/keepalive` so the free database never pauses.

## How we work (and keep token use low)

- **Claude Code in this folder is where the building happens:** plan, edit, `npm run build`, commit. Push `phase-1` only when Sarthak says so. Where we are and what's next is in `docs/plan.md`; read it at the start of a session and update it at the end of each part.
- **Models:** Sonnet is the default (`.claude/settings.json`). Switch with `/model` to Opus only to plan a new part or for a bug Sonnet can't crack, then switch back.
- **Bulk reading never goes in the main conversation.** Anything that means reading many web pages or long API answers goes to the `fetcher` agent (Haiku, `.claude/agents/`) or a script in `scripts/`; only a short summary comes back. Checking pages after a change goes to the `checker` agent.
- **Test with real data locally:** `npm run dev` on this computer reaches TMDB, Open Library and Google Books with the keys in `.env`. Check the preview on Vercel only when something depends on Vercel itself.
- One part of the plan per session; `/clear` between parts; small, specific requests.
- Commits are Sarthak's: no "Co-Authored-By" lines (`includeCoAuthoredBy` is off in `.claude/settings.json`). Never open or print `.env`.

## Rules Sarthak cares about

- **Never change the colours or quality of the paintings.** No filters, glows or overlays that tint them. Text goes in the quiet parts of a painting (sky, empty wall), never on a box over it.
- Motion stays subtle and slow, and nothing bends or warps the painting. Always respect `prefers-reduced-motion`.
- Keep the layout symmetrical and calm. No handwriting, tape or "moodboard" decoration.
- Keep explanations plain and non-technical.
- **Writing on the site:** plain, specific words. No em dashes anywhere (use a full stop, comma or brackets). No "Headline, *italic ending.*" pattern and no cute filler lines.
- The logo is the bookmark reel (`src/components/Logo.astro`, `public/favicon.svg`). The glossy 3D renders (`public/img/mark-3d-{day,night}.webp`) only where it's shown large.
- Colours: the accent `--lat` is peacock teal (#0F6A66 by day, #6CC9BF by night). Books use `--book` (coffee), films and TV `--sky`, essays `--moss`. Teal is for actions; filters and details use flat grey chips (`.gchip`). No orange accents.
- **Privacy first:** every new table gets row level security and explicit grants in `supabase/schema.sql` (this project doesn't expose new tables automatically). Private accounts, "Only me" entries and blocks must hold in the database, not just in the page.
- Never ask for or handle passwords, keys or tokens in the chat. They go in Vercel and `.env` only.
- Never create a sign-in session for any account, including Sarthak's, without asking first.
- **Never run `npm run db:apply` (or any script that changes the live database's structure) unless Sarthak asks for it in that same message.** Always run it with `--dry` first, show the output, and wait for his yes before the real run. A yes to an earlier run doesn't carry over to the next.
- Never add Claude as a co-author on commits.

## Commands

- `npm run dev` starts a local copy at http://localhost:4321 (needs the Supabase values in `.env`).
- `npm run build` builds the site. Run it before every commit.
- `npm run migrate` copies the old markdown library onto the `sarthak` shelf (replaces that shelf; run it once, just before switching over).
- `npm run trivia` fills in missing "Behind the film" facts.
